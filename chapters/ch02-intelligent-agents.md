# 第2章 智能体 (Intelligent Agents)

## 核心思想
AI 的正确研究框架是"智能体设计"：智能体通过传感器感知环境、通过执行器作用于环境；理性智能体对每个可能的感知序列选择期望最大化性能度量的动作。任务环境的属性决定智能体程序的设计，一切智能系统可归纳为少数几种基本智能体程序的组合与学习。

## 框架
- **智能体函数 / 智能体程序（agent function / agent program）**：函数是"感知序列→动作"的抽象数学映射；程序是其具体实现；智能体 = 架构 + 程序
  - 何时使用：分析或比较任何智能系统时
  - 如何做：程序只拿当前感知作输入；若动作需依赖历史，程序必须自行记住感知序列
- **PEAS 描述（Performance, Environment, Actuators, Sensors）**：指定任务环境的四元组
  - 何时使用：设计任何智能体的第一步
  - 如何做：先尽可能完整写出性能度量、环境、执行器、传感器，再谈算法
- **任务环境属性维度（Task Environment Dimensions）**：完全/部分可观测、单/多智能体、确定/非确定（随机）、回合式/序贯、静态/动态（半动态）、离散/连续、已知/未知
  - 何时使用：为问题选择智能体技术路线时
  - 如何做：逐维分类；最难组合=部分可观测+多智能体+非确定+序贯+动态+连续+未知（出租车驾驶）
- **四类基本智能体程序（Basic Agent Programs）**：简单反射型 → 基于模型的反射型 → 基于目标的 → 基于效用的，逐级增加显式信息
  - 何时使用：按环境可观测性与决策复杂度选型
  - 如何做：完全可观测用条件-动作规则即可；部分可观测需内部状态+转移模型+传感器模型；多目标权衡需效用函数
- **学习型智能体（Learning Agent）**：性能元素 + 学习元素 + 评估者（critic）+ 问题生成器
  - 何时使用：环境未知或先验知识不完整时
  - 如何做：评估者按外部性能标准给反馈，学习元素修改各组件，问题生成器建议探索性动作

## 关键概念
- **感知序列（percept sequence）** — 智能体感知到的完整历史；理性选择只依赖感知序列与先验知识。
- **性能度量（performance measure）** — 对环境状态序列的可取性打分；应按"真正想实现的目标"而非"以为智能体该如何表现"来设计。
- **理性智能体（rational agent）** — 给定感知序列提供的证据与先验知识，选择期望最大化性能度量的动作。
- **全知（omniscience）** — 预知行动实际结果；与理性区别：理性最大化期望性能，完美最大化实际性能，后者不可实现。
- **自主性（autonomy）** — 智能体通过自身感知与学习弥补先验知识缺失，而非依赖设计者内置假设（反例：粪甲虫、掘土黄蜂的固有规划）。
- **信息收集（information gathering）** — 采取行动改变未来感知（如过街前"观察"），理性的重要组成部分。
- **转移模型与传感器模型（transition model / sensor model）** — 世界如何随动作演变 / 世界状态如何反映在感知中；二者结合追踪部分可观测世界。
- **期望效用（expected utility）** — 按结果概率加权的平均效用；基于效用的智能体选择最大化期望效用的动作。
- **原子/因子化/结构化表示（atomic / factored / structured）** — 状态为黑盒 / 属性值向量 / 带关系的对象；表达力递增，推理复杂度递增。
- **局部/分布式表示（localist / distributed）** — 概念与记忆位置一一对应 / 分布于多个位置；分布式对噪声更健壮（相近点=相近含义）。

## 思维模型
- 把任何系统问三个问题：它的 PEAS 是什么？环境在哪些维度上"难"？需要哪一级智能体程序。
- 当性能度量会诱导刷分行为时，把度量改成"状态本身"而非"行为过程"（干净地板 vs 吸尘量）。
- 把表驱动智能体当作反例基线：|P|^T 条记录不可存储、不可设计、不可学习——AI 的核心是"小程序代替大表"。
- 当多个目标冲突或无法确定实现时，把目标升级为效用函数做加权权衡。

## 反模式
- **表驱动智能体（table-driven agent）**：查找表以感知序列为索引，含 Σ_{t=1..T}|P|^t 条记录——出租车驾驶 1 小时需 >10^(6×10^11) 条（单摄像头输入约 70 MB/s：30 帧/s × 1080×720 像素 × 24 位）；即使国际象棋也至少 10^150 条；可观测宇宙原子 <10^80——无空间、无时间、学不完。
- **简单反射型智能体用于部分可观测环境**：无位置传感器的真空吸尘器只有 [Dirty]/[Clean] 两种感知，确定性规则必然陷入无限循环；补救是随机化（抛硬币选左右），但更好的做法是升级到基于模型的智能体。
- **把性能标准放进智能体内部让它自行修改**：评估者必须在智能体之外固定，否则智能体会篡改标准以适应自己的行为。

## 算法要点
图2-7 Table-Driven-Agent（表驱动智能体，忠实转录）：
```
function Table-Driven-Agent(percept) returns 一个动作
   persistent: percepts，初始为空的序列
               table，以感知序列为索引的动作表，初始为完全确定
   将 percept 添加到 percepts 的末尾
   action ← Lookup(percepts, table)
   return action
```
关键：每个新感知都调用该程序并返回一个动作；内存中保留完整感知序列。注定失败，见"反模式"。

图2-8 Reflex-Vacuum-Agent（两方格真空吸尘器环境的简单反射智能体程序，实现图2-3 的智能体函数）：
```
function Reflex-Vacuum-Agent([location, status]) returns 一个动作
   if status = Dirty then return Suck
   else if location = A then return Right
   else if location = B then return Left
```
关键：忽略感知历史，把相关感知序列数从 4^T 减到 4——小程序代替大表。

图2-10 Simple-Reflex-Agent（简单反射智能体）：
```
function Simple-Reflex-Agent(percept) returns 一个动作
   persistent: rules，一组条件–动作规则
   state ← Interpret-Input(percept)
   rule ← Rule-Match(state, rules)
   action ← rule.Action
   return action
```
关键：仅当环境完全可观测（当前感知含决策所需一切）时才正确。

图2-12 Model-Based-Reflex-Agent（基于模型的反射智能体）：
```
function Model-Based-Reflex-Agent(percept) returns 一个动作
   persistent: state，智能体对世界状态的当前理解
               transition_model，关于下一个状态如何决定于当前状态和动作的描述
               sensor_model，关于当前世界状态如何反映到智能体感知的描述
               rules，一组条件–动作规则
               action，最近的动作，初始为空
   state ← Update-State(state, action, percept, transition_model, sensor_model)
   rule ← Rule-Match(state, rules)
   action ← rule.Action
   return action
```
关键：用内部模型追踪不可观测的世界部分，然后与反射智能体一样用规则选动作；无论环境怎样部分可观测、表示怎样不同，这一"追踪状态→匹配规则"骨架不变。

## 完整示例
**真空吸尘器世界（vacuum world）**：两方格 A、B，各可脏可净。
- PEAS：性能=每步每干净方格 +1 分（1000 步生命周期）；环境=地理先验已知、灰尘分布与初始位置未知；执行器=Left/Right/Suck；传感器=位置 + 当前方格是否脏。
- 状态空间：2（位置）×2（A 脏否）×2（B 脏否）= 8 状态；n 方格则 n·2^n。
- 智能体函数：即图2-3 表项与图2-8 程序（脏则 Suck，否则按位置左右移动）—— 在上述 PEAS 下是理性的（期望性能不劣于任何其他智能体函数）。
- 理性的条件性：若每动作罚 1 分则全清后继续移动不理性（应不做任何事）；若方格会再变脏则应巡视；若地理未知则须探索。同一函数理性与否取决于环境四要素。
- 此函数是简单反射型（只看当前感知），且仅需 4 种感知组合，对照表驱动的 4^T 条记录可见"小程序代替大表"。

## 要点
1. 设计智能体第一步永远是完全指定任务环境（PEAS），而不是选算法。
2. 理性 = 期望最大，不要求全知；信息收集与学习是理性的组成部分。
3. 环境维度直接决定技术选型：完全可观测+确定 → 反射规则就够；部分可观测 → 内部状态+模型。
4. 显式表示目标/效用换取灵活性：换目标只需改目标描述，不必重写全部条件-动作规则。
5. 学习型智能体四组件中，评估者的性能标准必须固定在外部；问题生成器负责用短期次优换取长期信息。
6. 表示轴（原子→因子化→结构化）贯穿全书：搜索用原子，CSP/规划/贝叶斯网用因子化，一阶逻辑/NLU 用结构化。
